This reference covers all 155 entries in the application's `.env.example`, plus relevant runtime and compatibility settings. It was checked against the repository configuration and readers on **1 November 2026**. Older deployed images may not support every setting, including the recently added branding options.

These variables belong to your **Open Inventory application**, not to this documentation website. See [Configure your instance](/configuration) for a short introduction and the [example environment file](https://github.com/Utzel-Butzel/inventory/blob/main/.env.example) for a starting point.

## Reading this reference

- **Default** means the behavior when the variable is absent, not necessarily the value supplied by `.env.example` or a deployment template. Differences are called out below.
- **Required** means required by the production startup script. **Conditional** means required only for the named feature. Other settings are optional.
- **Secret** marks credentials or sensitive configuration. Do not commit their real values or expose them through `NEXT_PUBLIC_` variables. An unmarked value may still contain private infrastructure information.
- Unless a section says **Build**, **Compose** or **Tool**, settings are **Runtime** settings. Restart the application process after changing them; recreate containers to load a changed container environment. Some settings are initialized only at startup.
- Use `true` or `false` for booleans. Numeric timeouts are milliseconds unless the name or table explicitly says seconds, minutes, hours or days. Limits described as **clamped** are restricted to the stated range.
- An empty string is not universally equivalent to an absent variable: numeric readers can interpret it as zero. Omit optional numeric overrides to retain their defaults, or provide an explicit valid number.

## Load settings and apply changes

For local development, put values in `.env.local` in the application repository root and restart `npm run dev`. Next.js prioritizes the process environment, then environment-specific local files, `.env.local`, environment-specific files and `.env`. `.env.local` is excluded in test mode.

For Docker Compose, `.env` supplies values for Compose interpolation. It does **not** automatically pass every variable into the container. Verify that the application service forwards the setting under `environment`, or add a mapping:

```yaml
services:
  app:
    environment:
      APP_NAME: ${APP_NAME:-}
      APP_LOGO_URL: ${APP_LOGO_URL:-}
```

The root Compose service is named `app`; the Dokploy and Coolify templates use `inventory`. The templates forward different subsets of settings. In particular, a setting described here may require an additional mapping in an older or custom deployment definition.

After runtime changes, recreate the application using the same Compose files used to deploy it. For the repository's local port override:

```bash
docker compose -f docker-compose.yml -f docker-compose.local.yml up -d --force-recreate app
```

In Dokploy or Coolify, save the environment and Compose mappings, then redeploy. `docker restart` alone does not change the container's environment. Build-time map settings require a new application build; see [Maps](#maps).

Keep bcrypt hashes in single quotes in Compose `.env` files so their dollar signs are preserved. Base64 is an encoding, not encryption.

## Password login and bootstrap

Runtime. Bootstrap configuration creates the first database-backed administrator only while no users exist; it is not a password-reset mechanism for existing users. Prefer database-managed users after initialization.

| Variable | Default | Format / requirement | Purpose and notes |
| --- | --- | --- | --- |
| `AUTH_PASSWORD_ENABLED` | `true` | Boolean | Enables password sign-in, including the native password-to-token endpoint. Configure and test another login method before disabling it. |
| `BOOTSTRAP_ADMIN_EMAIL` | `SIMPLE_AUTH_EMAIL`, then `admin@inventory.local` | Email address | First administrator's email, normalized to lowercase. |
| `BOOTSTRAP_ADMIN_NAME` | `SIMPLE_AUTH_NAME`, then `Inventory admin` | Text | First administrator's display name. |
| `BOOTSTRAP_ADMIN_PASSWORD_HASH` | `SIMPLE_AUTH_PASSWORD_HASH`, then unset | Bcrypt hash; **Conditional, Secret** | Initial administrator credential. Generate with `npm run auth:hash -- "your password"`. Do not combine with `BOOTSTRAP_ADMIN_PASSWORD`. |
| `BOOTSTRAP_ADMIN_PASSWORD` | Unset | At least 12 characters; **Conditional, Secret** | One-time plaintext bootstrap input. Production accepts it only with `BOOTSTRAP_ADMIN_PASSWORD_ONCE=true`; startup hashes it before loading the app. |
| `BOOTSTRAP_ADMIN_PASSWORD_ONCE` | `false` | Boolean | Enables one-time plaintext handling. After creating the admin, remove both plaintext bootstrap settings from the deployment and change the password in the app. |
| `SIMPLE_AUTH_EMAIL` | `admin@inventory.local` | Email address | Legacy fallback for bootstrap email. |
| `SIMPLE_AUTH_NAME` | `Inventory admin` | Text | Legacy fallback for bootstrap display name. |
| `SIMPLE_AUTH_PASSWORD_HASH` | Unset | Bcrypt hash; **Secret** | Legacy fallback when the bootstrap hash is absent. |
| `SIMPLE_AUTH_PASSWORD` | Unset | Text; **Secret; development only** | Legacy plaintext input. The production startup script rejects it. |
| `NATIVE_TOKEN_TTL_DAYS` | `30` | Integer, 1–365 days | Lifetime of newly issued native login tokens. Invalid values fall back to 30. |

The production entrypoint removes plaintext bootstrap values from the app process after hashing; it cannot remove them from the saved deployment environment. Remove them there yourself after initialization.

## External sign-in

| `AUTH_OIDC_CLIENT_SECRET` | Unset | Credential; **Conditional, Secret** | OAuth client secret. |
| `AUTH_OIDC_SCOPES` | `openid email profile` | Space-separated scopes | OIDC scopes requested during sign-in. |

## Storage and upload limits

Runtime. Paths are resolved inside the app process/container. Mount persistent storage where the process can write; the standard container uses UID/GID 1001.

| Variable | Default | Format / requirement | Purpose and notes |
| --- | --- | --- | --- |
| `STORAGE_PROVIDER` | `local` | `local` or `openinary` | Selects upload storage. |

| `IMAGE_VARIANT_CACHE_PATH` | `.variants` under the local storage path | Filesystem path | Cache of resized images. Add an environment mapping if your deployment template does not forward it. |

**Build.** All three map variables are public client-bundle settings. Set them before `next build`; the Dockerfile accepts them as build arguments. Changing the runtime environment of a prebuilt image does not update maps. Never place private credentials in these variables.

| Variable | Default | Format / requirement | Purpose and notes |
| --- | --- | --- | --- |
| `NEXT_PUBLIC_MAPBOX_ACCESS_TOKEN` | Unset | Public Mapbox token | When present, Mapbox streets/satellite tiles take precedence over the fallback URLs. |
| `NEXT_PUBLIC_MAP_STYLE_URL` | `https://tiles.openfreemap.org/styles/liberty` | MapLibre-compatible style URL | Street/room map fallback when no Mapbox token is configured. |
| `NEXT_PUBLIC_SATELLITE_TILE_URL` | `https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/{z}/{y}/{x}` | Raster tile URL template | Satellite fallback when no Mapbox token is configured. |

For a source-based Docker deployment, set the values in `.env` and rebuild with the same Compose files used for installation, adding `--build` to `up -d`. For an image-based platform template, publish/use an image built with the intended values.

### Paid-AI request limits

Per-identity request limits are separate from provider billing limits. Integers from 0 to 1,000,000 are accepted. **Zero disables the operation. A malformed explicit value also disables it.**

For analysis, research, recognition and counting, precedence is: operation-specific value → `AI_RATE_LIMIT_PER_MINUTE` → built-in operation default. Blank overrides are skipped. The example file and root Compose template explicitly set the legacy limit to 10, so research inherits **10**, rather than its built-in default of **5**, unless overridden.

| Variable | Default when absent | Format | Operation |
| --- | --- | --- | --- |
| `AI_RATE_LIMIT_PER_MINUTE` | Per-operation defaults below | Integer / minute | Legacy fallback shared by four operations; example/template value is 10. |
| `AI_ANALYSIS_RATE_LIMIT_PER_MINUTE` | Legacy value, otherwise `10` | Integer / minute | Image analysis. |
| `AI_RESEARCH_RATE_LIMIT_PER_MINUTE` | Legacy value, otherwise `5` | Integer / minute | Web research. |
| `AI_RECOGNITION_RATE_LIMIT_PER_MINUTE` | Legacy value, otherwise `10` | Integer / minute | Item recognition. |
| `AI_COUNT_RATE_LIMIT_PER_MINUTE` | Legacy value, otherwise `10` | Integer / minute | Photo counting. |
| `AI_TRANSLATION_RATE_LIMIT_PER_MINUTE` | `30` | Integer / minute | Content translation; no legacy fallback. |
| `AI_IMAGE_RATE_LIMIT_PER_HOUR` | `60` | Integer / hour | Cover generation; no legacy fallback. |

## MCP endpoint

Runtime. Enable the optional endpoint at `POST /mcp`. It accepts Inventory API bearer tokens scoped to their issuing organization, not browser sessions or `X-Organization-ID` overrides.

## Secrets and verification

Generate a new value separately for each encryption purpose. For variables requiring 32 random bytes as 64 hexadecimal characters:

```bash
openssl rand -hex 32
```

Preserve encryption keys together with protected deployment backups. Replacing `WEBHOOK_ENCRYPTION_KEY`, `INTEGRATION_ENCRYPTION_KEY` or `NOTIFICATION_ENCRYPTION_KEY` without a migration/re-enrollment plan can make existing encrypted data unreadable. Changing signing secrets can invalidate sessions or pending signed jobs.

After applying changes, check `/api/health` and the feature you configured. A healthy database/storage check does not verify SMTP credentials, model access, OAuth callbacks or a remote logo. Review application logs for validation errors without publishing environment dumps or rendered Compose secrets.

When updating this reference, compare `.env.example`, the relevant code readers and the deployment mappings. Keep example values distinct from built-in defaults, and verify newly added settings against the version you deploy.
